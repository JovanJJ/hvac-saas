# Field and office experience

The primary mobile journey is “Danas” → site → system → outcome → visit summary. Use Serbian Latin for field labels and plain language for errors. Separate the technician's daily work from the office review queue. The same responsive application supports both.

## Screens and journeys

| Screen | Required behavior |
| --- | --- |
| Sign-in and onboarding | Owner creates a workspace, sets company name and local time zone, imports the first site or enters one manually. Solo users can assign a visit to themselves. Invited technicians land directly on Today. |
| Today | Time, site, address, site contact, count of systems, access note and offline availability. Tap to call or navigate. Show previously downloaded assignments when disconnected. |
| Site and equipment | Search by system code, room/position or serial. Open the previous finding, last service and plate photo. Show which physical units belong to the system. A system awaiting a part remains identifiable at the next visit. |
| Field form | One card per system. Use visit-type templates for maintenance, repair and installation. Make work done and outcome easy to enter; reveal reading, unit, mode, material, photo/caption and follow-up fields when needed. Record outcomes deliberately. |
| Visit summary | Count planned and inspected systems separately, list unfinished items and required follow-ups, identify the pending photo or missing owner that blocks submission. Solo owners can proceed to issue after a successful submission. |
| Office workspace | Day/week schedule, assignment, recurrence, customer/site register and import preview. Provide separate queues for missing confirmations, follow-ups, return appointments and billing review. Each row links to its underlying finding. |
| Report and receipt | Staff preview the final layout, issue, share and revoke a link. Recipients can read or download without signing in and choose whether to acknowledge receipt. Present report details before asking for acknowledgement. |

## Offline scope

Use a service worker for versioned application-shell assets and IndexedDB for explicitly downloaded visit bundles, edit operations and pending photos. Ordinary browser HTTP caches are unsuitable for private visit bundles. Partition device records by signed-in account and organization. Do not cache office exports or guest links. An initial authenticated online download is required; show readiness per visit and warn if pending photos or storage limits make it incomplete.

Show states in words as well as icons: “Dostupno bez interneta”, “Sačuvano na telefonu”, “Slanje u toku”, “Sinhronizovano”, “Potrebna provera”. Save each meaningful field change to local storage. Queue stable operation IDs and base versions; replay when the app is active and online, including an explicit retry action. Support closing and reopening the app. Do not promise synchronization while the browser is closed.

Remove confirmed local operations after server acknowledgement. For conflicting work show the local and server values, who changed the record if available and an explicit resolution action. Do not silently overwrite either copy. Expired sessions prompt reauthentication before upload. On reassignment/access denial lock editing and remove stale accessible data; never send the draft using a different user or organization. On logout warn about unsynced work and allow sync first or explicit discard, then clear private device data. Explain that revocation takes effect on an offline device when it reconnects.

## Field usability and acceptance

- Prioritize the day's task and room label over internal IDs. Large touch targets, readable contrast, explicit labels, keyboard operation, visible focus and non-color status cues are baseline requirements.
- Keep “not measured” distinct from numeric zero. Support Serbian decimal comma input, normalize on submission and present units next to the value. Keep field values when validation fails.
- Ask once for site/visit details and reuse them across its systems. For a no-access item ask for the reason and next action instead of opening measurement fields.
- Accept camera and file input with a clear preview. Show storage failure immediately and preserve the existing draft if a new photo cannot be saved.
- Validate on a narrow phone, an office desktop, a keyboard-only session, and a real phone going offline and reconnecting. Test both compact single-system and long multi-system visits. Time the actual workflow with pilot users before setting a speed target.

The device identity status identifies whether the current account/workspace has been verified. **Dostupno bez veze · samo pregled** appears only after the exact shell revision is installed and the IndexedDB transaction commits. Failed initial writes never show readiness; failed refresh/removal retains the previous committed copy and reports the error. Downloads show their capture time.

The manifest starts at `/today`. A full offline navigation to Today or `/visits/[visitId]` falls back to a public, data-free HTML/JS shell. **Preuzete posete na ovom telefonu** also opens that shell directly. Auth/workspace transitions invalidate that binding before submission across tabs; server-side epoch rotation also protects redirects, callbacks and stale responses. Logout clears read-only copies and locks retained drafts with their source bundles until the same account/workspace is verified again. Workspace changes retain other partitions but hide them until that identity/workspace is verified again. Reconnection removes copies no longer assigned; older inventory responses cannot restore a known withdrawn assignment. No browser Auth credential is stored in this database.

### M4b durable field drafts

Scheduled/in-progress downloads offer **Dostupno bez veze · lokalni unos**; submitted/issued downloads remain read-only. Each field change is committed in IndexedDB before **Sačuvano na telefonu · nije poslato** appears. The reusable React editor restores exact raw inputs after browser restart, including deliberate pending outcomes, measured zero, unmeasured null, decimal material quantities and incomplete follow-up ownership/deadlines. Invalid or incomplete inputs remain recoverable locally; preparing a payload uses the online item schema and never turns an empty measured value into zero. Office-managed actions stay read-only.

The `drafts` store is keyed by `[userId, organizationId, visitId, itemId]`, indexed by visit and partition. Records retain actor identity/label, captured source attribution, base visit/item versions, a stable operation ID, timestamps, local revision and raw form values. Each write checks the active identity/epoch, assignment and source bundle, editable visit state and expected local revision. A competing tab cannot silently overwrite a newer draft. Failed writes retain the previous committed draft and show unsaved input with retry.

**Pripremi za slanje** freezes a validated canonical payload and shows **Čeka slanje · nije potvrđeno na serveru**. M4b introduced this local queue; M4c now adds the foreground sender and queued handover described below. An unattempted queued draft can explicitly return to editing using the same operation ID; M4c marks an attempt before transport and preserves the attempted payload. Local summaries are labeled unconfirmed. The online visit form pauses while this device has pending drafts so an older server summary cannot be submitted accidentally.

Refreshing a downloaded visit with drafts is blocked; removing it uses the lifecycle choices below. A draft can be explicitly discarded per system, with confirmation; this never changes server data. Account/workspace changes hide pending work and invalidate open tabs, but do not silently erase committed drafts. Reverification of the same authorized identity restores them. Withdrawal removes the accessible source bundle and leaves locked draft evidence; reviewed recovery is implemented in M4e; M4f adds the lifecycle/discard choices below. Browser storage clearing/eviction can still remove device work; physical-device/storage lifecycle checks remain M4f.

### M4c foreground synchronization and queued handover

In a downloaded visit, choose **Pripremi za slanje** for each edited system. This freezes a validated item payload. **Pripremi predaju kancelariji** validates the effective local visit (including pending outcomes and follow-up owners/deadlines) and stores a separate submission with a stable operation ID, expected aggregate version and prerequisite item operation IDs. Queueing does not mark the visit submitted. Further edits are blocked until an unattempted submission is explicitly cancelled. Server-side attachment validation remains authoritative; durable photo capture is now available through M4d below.

**Sinhronizuj sada** is available on Today and in the downloaded shell. With the app open, mounting a verified device view or restoring connectivity starts a bounded foreground pass; transient failures retry after 5/15/30 seconds. There is no closed-app/background-sync guarantee. Only queued items are sent; ordinary local drafts remain on the phone. A pass sends at most five items per request and twenty requests per visit. A further manual pass resumes larger queues.

IndexedDB schema 3 adds `submissions`, keyed by `[userId, organizationId, visitId]` with a partition index. Before transport, a transaction records `attemptedAt`; that operation ID, base version and payload cannot change while the result is uncertain. Successful acknowledgements atomically update the downloaded item/aggregate state and remove only the matching operation. Historical acknowledgements cannot roll back a newer item or aggregate version. **Potvrđeno na serveru** appears after this local commit. If a server response is lost or saving the acknowledgement fails, the same operation remains retryable. Concurrent senders are safe because the server deduplicates exact actor-scoped operations.

Submission is sent in a later request only after every item draft has been acknowledged. Its expected version is the captured aggregate version plus the queued item writes; concurrent unrelated changes can therefore cause a safe conflict rather than silent rebasing. Only a matching server acknowledgement changes the local visit to submitted and exposes its read-only summary. The office then sees the same persisted findings through ordinary review.

A failed later operation does not undo earlier acknowledgements. Conflicts/denied access pause the affected queue and retain the local draft; reviewed reconciliation is available through M4e below. A definitively rejected item (422) may return to editing under a new operation ID. An unattempted or definitively rejected submission can be cancelled and corrected; an uncertain attempted submission remains frozen for retry. Expired sessions lock the partition and retain pending work. Workspace/account transitions cannot apply an old response to another partition. Refresh/removal and ordinary online forms also protect pending submissions after their item drafts have been acknowledged.

### M4d durable photo outbox

Each editable downloaded system has **Fotografije** with camera/file input, required caption and explicit **Za klijenta / Interno** visibility. **Sačuvaj fotografiju na telefonu** atomically stores the Blob, immutable metadata, stable attachment UUID, captured actor and upload intent before displaying success. Supported files are JPEG/PNG/WebP up to 8 MiB; the server also verifies actual format and dimensions (up to 40 megapixels). A failed local write leaves the selection in the form and never claims a saved photo. No image bytes enter Cache Storage or browser credentials.

IndexedDB schema 4 adds `photos`, keyed by `[userId, organizationId, visitId, id]`, with visit/partition indexes. Blob previews use short-lived `blob:` URLs, revoked when the view closes or changes. Full browser restart restores exact bytes, caption, visibility, identity and attachment ID. Confirmed captured photos retain their local preview; existing server-only photos are not automatically downloaded. Signing out locks pending work and removes confirmed device copies; explicit removal of a downloaded visit clears its confirmed photo records. Pending photos block replacing/removing the source copy and ordinary online editing. Other accounts/workspaces cannot display those blobs. Withdrawn assignments hide their source and retained photo evidence until authorized recovery through M4e below.

Foreground/manual synchronization saves queued item edits, then processes up to ten photos per visit/pass, then submits only after every pending photo has been verified or its removal acknowledged. A saved photo is automatically queued; it needs no separate per-photo preparation button. Additional passes resume larger queues. Preparation, upload and completion reuse the M3a provider/verification flow. A completion probe before re-upload recovers an upload whose response was lost. Server requests generate fresh upload credentials and completion attestations; none are stored on the phone. Expired attempts retry after live authorization.

A photo records its first attempt before transport. Caption/visibility/bytes remain fixed for its attachment ID. Phase acknowledgements are committed locally with their cumulative version effects; duplicate or out-of-order responses cannot count a phase twice or revive a removed photo. An unattempted queued submission adds only those known local photo effects to its expected aggregate version, preserving conflict checks for unrelated writes. It remains unsubmitted while evidence is pending or failed.

Invalid/provider failures retain the file and expose **Ponovi slanje fotografije** and explicit removal. A never-attempted photo can be discarded locally. After an attempt, **Ukloni neposlatu fotografiju** records removal intent, retains bytes and waits for a server tombstone before releasing the Blob. Removal also works while an unattempted submission is waiting, so the user can deliberately exclude failed evidence. Provider cleanup failure is shown separately after the attachment is inaccessible; cleanup can be retried. Reviewed conflict/access recovery is available in M4e; shared-device/storage-pressure choices remain M4f. Physical iOS/Android camera/installation checks remain the M4f gate.

### M4e reviewed conflicts and retained access

A stale item or submission shows **Potrebno je usaglašavanje** in the downloaded visit. **Učitaj trenutno stanje** reads a fresh assigned-only server snapshot, exact operation receipt status and safe photo metadata. The comparison shows local/server outcomes, work, finding, access reason, internal note, zero/unmeasured readings, parts, follow-up ownership/deadline/customer dependency and current author/version. Handover compares all current systems and evidence before choosing a replacement. Current values are those read at review time; another edit after review still conflicts on the server.

After checking **Pregledao/la sam obe verzije i fotografije**, **Nastavi lokalni nacrt** retains the chosen raw inputs under a new operation UUID and the reviewed item version. It returns to editable local state; the technician can merge further changes and prepare/synchronize again. Office-managed follow-ups remain fixed to their reviewed server fields, as explained in the comparison. **Zadrži podatke sa servera** adopts those values locally without rewriting their server authorship or version. The replaced draft and any cancelled local handover are retained in a scoped recovery history. An uncertain attempted operation cannot be abandoned this way; committed receipts are acknowledged instead.

For a rejected final handover, **Pripremi novu predaju** creates a fresh submission against the reviewed aggregate version. Item drafts and pending photos must be resolved/confirmed first. The old ID/payload stay in recovery history. The replacement is not sent until foreground/manual synchronization and cannot silently adopt changes made after review. No report is automatically issued: successful handover enters office review, then the owner issues it normally.

IndexedDB schema 5 adds `blocked` source copies and `recoveries` history, both partitioned by user/organization. Verified inventory withdrawal moves a pending source copy out of accessible bundles while retaining drafts, Blobs and original operation IDs. **Zadržan rad · pristup nije potvrđen** shows only short visit identifiers and pending counts, not site details, findings or image previews. **Proveri pristup ponovo** rechecks live assignment and restores the copy only for the same authorized identity/workspace. It also supports older releases that retained operations after deleting their source snapshot. Neither path rebases queued item versions automatically.

Expired sessions lock local access and show **Prijavi se ponovo**. After sign-in, replay resumes original IDs only for current assignments under that account/workspace. Reverification clears authorization denials only; stale-version conflicts remain paused for explicit review. Another account/workspace cannot activate retained records. A conflict pauses that visit's replay/photo work while other visits can continue. An online Today view checks an already-installed shell for updates; reopen the downloaded visit to use the new recovery UI. No site-storage reset is required. M4f adds device upgrade and cleanup/discard handling below. Physical-phone acceptance remains pending.


### M4f device lifecycle and upgrades

Sign-out/session changes and workspace switches (including workspace creation and invitation acceptance) pause before the server action when the current partition has pending work. Sign-out also asks when downloaded copies remain. **Zadrži na uređaju i nastavi** locks those private copies for the original account/workspace; it does not send ordinary drafts. **Sinhronizuj pa nastavi** runs the existing foreground replay and continues only after a fresh device read confirms no pending work in the affected scope. Unprepared drafts, conflicts, unavailable sessions, withdrawn assignments and network failures keep the transition paused. It never silently prepares a draft or queues a handover.

Removing a downloaded visit offers **Zadrži posetu**, sync before removal, or an explicit checkbox followed by **Obriši lokalno i nastavi**. Removal covers the source, drafts, submissions, photo Blobs, withdrawn source and recovery history for that visit. Discard affects local data only. Attempted pending commands/photos and outstanding provider cleanup block discard because their server result may be uncertain; sync, photo removal or reviewed recovery must settle them first. An atomic removal rechecks pending work, so another tab cannot sneak a new pending record into a safe removal.

**Očisti podatke ovog uređaja** is available in staff/auth screens and the standalone shell, including when logged out. It explicitly names all accounts and deletes every private store plus the active identity in one IndexedDB transaction, then invalidates other tabs. It does not delete server findings, attachments, replay receipts or issued reports. Any attempted pending work in any partition blocks this cleanup. Use the original account/workspace to settle that work first; no force-discard bypass is provided. A transaction failure retains prior committed records and never reports successful cleanup. Shared-device keep is not cleanup: sign out and use explicit cleanup before handing over the device.

In the current window, unsaved/in-flight field input and uncommitted photo selection block lifecycle actions and request the browser's ordinary navigation warning. The browser may suppress that warning, so only a committed **Sačuvano na telefonu** state establishes durability. If IndexedDB cannot open, auth/workspace transitions can still continue with explicit keep after a warning; the cross-tab marker is invalidated before storage access, and the server rotates the identity epoch. Cleanup/removal never bypass a storage failure.

The worker precaches the complete new public shell but does not call `skipWaiting`. An update waits until all app windows close. The existing shell continues serving its own assets, without a forced reload of active forms. **Nova verzija je spremna** instructs saving forms, closing all windows and reopening; a download requiring the new revision stays unconfirmed until activation. Activation removes obsolete public caches only, never IndexedDB. Schema 5 remains unchanged in M4f; additive upgrades retain committed records and close connections on `versionchange`. Blocked storage shows close-other-windows/retry guidance, without a database reset.
